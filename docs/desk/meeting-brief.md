# Meeting evidence without a model

`POST /api/desk/meeting-brief` accepts only `{ "event": "cal:source:event", "refresh": true }`; `refresh` is optional. The event is an opaque key from the current Desk calendar source. `GET /api/desk/meeting-brief?event=...` reads a prepared resource. Both methods require the existing MC Host, Origin and principal identity gates.

Every request rereads configured sources and linked built-in material. Facts include the source's excerpt or link; saved link titles are never evidence. New Mail link snapshots retain the source connection; reads require that connection and the recorded account. Legacy links without a recorded connection fail closed until relinked; a newly configured connection cannot inherit them. Built-in Balance, Studio and Desk notes identify their owner with `adapter: null`. Configured calendar/Mail commands identify their built-in `SourceCache` command owner as `desk-source-command`, with `adapter: null`; this is an evidence-owner classification, not a registered adapter. Balance uses its existing structured owner authorization check: a task whose area is no longer configured is an `access-denied` gap. Command source failures have no structured denial signal and remain `read-failed`; their private error text is never classified or exposed. No model or previous-meeting discovery runs. `previousMeeting.state` is `unidentified`; `synthesis.state` is `unavailable`, with `reason: not-configured`.

Revisions include the meeting, its source configuration and connection, linked evidence content and coverage. A changed or failed source causes GET to return `409 refresh-required` without the prepared facts; prepare again to receive current evidence and named gaps. An unavailable or gone meeting returns 404. Source failures never expose private error details. Responses contain `Cache-Control: no-store`.

The new endpoint-scoped [v1 examples](examples/meeting-brief-v1.json) pin successful preparation and malformed, stale and gone failures. They are exercised through the real authenticated HTTP route by `bun scripts/probe-desk-meeting-brief.ts` and its test. Only the opaque revision and preparation timestamp are normalized when comparing a successful example. This fixture version is an example-pinning convention introduced for this endpoint; it does not add an API-wide handshake, response header or SDK version. The map's planned API-wide compatibility mechanism remains separate work.

The probe uses a temporary database, synthetic calendar/Mail command and explicit task/note/Mail links, with no model or production credentials. It reads the brief, verifies identity/Origin/Host refusals, removes Mail, verifies the stale conflict, refreshes to a named Mail gap, then removes the meeting and verifies 404. All temporary resources are removed when it finishes.
