# Open a configured local bus from an application

`startConfiguredMyelinRuntime(configPath, { expectedStackId, expectedNkey, jetstreamDomain?, connectTimeoutMs? })` is an additive export from `@the-metafactory/cortex/bus`. It loads and validates the existing Cortex configuration, requires explicit stack/public-key pins and private native credentials, then constructs the signer inside Cortex. Applications receive a `MyelinRuntime`; the public API does not expose signing material. This is an API boundary inside a trusted application process, not process isolation or a credential sandbox.

Only explicit `nats:` loopback URLs without userinfo, backslashes, path, query or fragment are accepted. mTLS-enabled configurations are refused, so unsupported policy is never weakened. The connection uses one validated server and ignores advertised cluster updates. Initial connection fails within `connectTimeoutMs` (100–30,000 ms, default 5,000 ms), without daemon-style retry or background connection attempts. Native runtime operational messages still go to stdout; applications must account for these messages instead of assuming JSON-only output. The helper adds `-sdk` to the configured connection name, opens no initial subscriptions, and does not start agents, dispatch consumers or federated links. All publish methods reject non-local classification, and explicit subjects must stay within the pinned local stack. Normal native reconnection remains enabled after a successful initial connection. Applications that subscribe must validate their inbound policy and signatures themselves. Stack signatures identify a stack key, not a particular application, assistant or execution host. The existing legacy stack-to-DID spelling is preserved; verifiers must bind the expected DID to its pinned public key.

The helper always refuses unsigned fallback, including under permissive signing posture. This intentionally makes its publish behavior stricter than the daemon's permissive default. Missing signing material fails bootstrap. A defensive guard also refuses a disabled runtime if future native runtime changes introduce that state. `publishDurable` provides an acknowledged result or throws; ordinary Core NATS publishing does not prove consumer receipt and can report a dropped publish through native logs. Use explicit bounded application deadlines and durable outer work delivery where recovery is required.

The SDK release must be pinned by consumers. The consuming SDK validates configuration with its own schemas and loads configured agent/persona information through the existing loader, so an incompatible configuration fails closed. Updating an application's SDK does not upgrade or reload an installed Cortex service.
