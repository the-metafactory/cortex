# ADR-0024 — Pluggable surface adapters: out-of-tree, arc-installable, compat-gated, in-process

**Status:** **proposed** (HOLD — awaiting principal ratification; do NOT merge as accepted) · **Date:** 2026-07-09 · **Lifts the deferral in:** [ADR-0017](0017-surface-tooling-arc-bundles.md) §Alternatives L64–67 (0017 itself is NOT edited) · **Refs:** epic [#1784](https://github.com/the-metafactory/cortex/issues/1784), S0 [#1785](https://github.com/the-metafactory/cortex/issues/1785), `docs/design-pluggable-adapters.md`, [ADR-0012](0012-external-operator-account-isolation.md) (process-isolation precedent), [ADR-0018](0018-admission-gate-and-leaf-secret-distribution.md)/[ADR-0023](0023-federation-leaf-credential-model.md) (signing precedent), `src/gateway/gateway-adapters.ts`, `src/common/types/surfaces.ts`, `src/adapters/types.ts`, F-092 (config hot-reload), C-110 (web adapter)

## Context

Cortex compiles all four surface adapters (`src/adapters/{discord,mattermost,slack,web}/` — 2 858 / 1 469 / 1 189 / 535 LOC) into core, and their platform npm deps sit in cortex's own `package.json:47-55`. Adding, upgrading, or removing a surface requires a whole-cortex release, and every stack carries every surface's dependency weight.

[ADR-0017](0017-surface-tooling-arc-bundles.md) extracted the surface *tooling* into per-surface arc bundles (`metafactory-discord`, epic #1171) and **explicitly deferred the adapter**: *"Extract the adapter too … Rejected for now — the adapter is deeply woven into the bus/dispatch/surface-router; a plugin adapter model is a much larger change. Deferred to a separate future ADR; this ADR extracts only the cleanly-decoupled tooling layer"* (`0017-surface-tooling-arc-bundles.md:64-67`). **This ADR is that future ADR.** It extends ADR-0017's arc-bundle shape from the tooling layer to the adapter layer.

The stocktake grounding this decision is in `docs/design-pluggable-adapters.md` §2 (verified @ v6.7.0). The adapter contract is already clean (`src/adapters/types.ts:183-264`: `start/stop`, `updateConfig?`, `attachInboundDispatch?`), and both construction paths already route through one injected factory (`src/gateway/gateway-adapters.ts:264-347`; the S9/cortex#1523 `wireSurfaceAdapters` extraction). The residual couplings are enumerated as blockers #5–#8/#13 in the design doc.

## Decision

**Surfaces become pluggable adapters: per-platform arc bundles a principal installs/upgrades/removes independently of cortex releases, discovered and loaded by the running daemon behind a versioned adapter SDK, compat-gated at load, fail-isolated per bundle, running in-process.** The four pinned decisions:

**D1 — Compat gate: SDK semver range, authoritative at the loader.**
Cortex exports a single-integer-major `ADAPTER_SDK_VERSION`. A bundle declares an `sdkRange` (e.g. `^1`) in its default-exported `AdapterModule`. **The loader** (runtime, inside the daemon) is the sole authoritative gate: it checks `satisfies(ADAPTER_SDK_VERSION, module.sdkRange)` at `await import()` time and refuses a non-satisfying bundle with a `system.error` event, leaving the daemon and all other adapters live. A `cortex: >=X <Y` version range MAY appear in `cortex-adapter.yaml` as **advisory** metadata (arc install may surface it), but it is **not** the load gate. *Rationale: the SDK version is the honest contract — it breaks only when the adapter API breaks — so it decouples surface compat from cortex's release cadence (the epic's core goal); a cortex-version gate re-couples them and goes stale on every unrelated cortex release. Only the running daemon knows its true `ADAPTER_SDK_VERSION`, so arc install can only warn.* Cost accepted: `ADAPTER_SDK_VERSION` is a disciplined semver contract — a breaking `PlatformAdapter`/`AdapterModule` change is a *major* bump with a documented bundle-author migration.

**D2 — Extraction deletes the in-tree adapter; the in-tree mock is the permanent contract anchor.**
Each extraction PR (S9–S12) removes the real in-tree adapter *and* its npm deps once its bundle is proven. There is **no real-adapter fallback** in cortex. The in-tree **mock** adapter stays permanently and drives the contract tests, so the registry always has an in-tree entry exercising both construction paths in CI. *Rationale: a fallback copy is a second source of truth and, decisively, the platform deps (blocker #8) cannot leave `package.json` while any in-tree module imports them — keep-as-fallback would never achieve the dependency extraction that is half the point.*

**D3 — v1 MVP is boot-time discovery; runtime load/unload/reload verbs are a separate slice (S8).**
v1 (S6) discovers, compat-gates, imports, validates, and registers bundles **at boot**; installing a bundle + restarting the daemon brings a surface live with no cortex release. Runtime `cortex adapter list|load|unload|reload` (S8) is a distinct, later slice carrying: module-cache busting (query-param import; the old module tree is dereferenced, not evicted — a **documented, bounded one-tree-per-reload leak**, so `unload` MUST `stop()` and drop every reference first), in-flight drain (inbound stops immediately; the outbound sink drains a bounded window then detaches — a mid-flight dispatch losing its sink is a `system.error`, never a silent drop), per-adapter attach/detach on gateway+router (blocker #13 — `surface-gateway.ts:167,191` is all-or-nothing today), and **state loss on reload by design** (adapter connection state + progress placeholders reset; nothing durable is lost — response routing is wire-level). *Rationale: boot-discovery delivers the epic's core value at low risk and fits the isolated trust-path review lane the wave plan gives S6; runtime verbs' complexity is sequenced after.*

**D4 — Adapters run in-process with full daemon authority; risk accepted for v1 with mitigations.**
A bundle loaded into the stack daemon has the daemon's full authority — the stack NKey seed (it can sign as the stack), config secrets, CC-session spawn, bash, filesystem — and `await import()` executes arbitrary bundle code at load. **A malicious/compromised bundle = full stack compromise. The compat gate is not a security gate; fail-isolation isolates crashes/incompat, not malice.** Accepted for v1 because every bundle is first-party. Mitigations: (1) **org-trusted repos only** — v1 loads only `the-metafactory` bundles via arc's repo-first install (ADR-0017), no by-name/third-party loads; (2) the **same blocking CI floor as cortex** on bundle repos (`check-shippable-hygiene.ts` + `confidentiality-gate`); (3) **provenance pinning** — arc pins repo+ref and a bundle upgrade is a code-review event, not a passive fetch; (4) **"fail-isolation ≠ sandbox" is stated** so the isolation guarantee is never over-read. **Named future escalation:** registry signing (mirrors ADR-0018/0023), and separate-process-over-IPC if a real trust boundary is ever required (the gateway's separate-process unsigned/stack-re-signs model, `CONTEXT.md:181`, is the partial precedent).

**Load posture (recommendation, pending OQ6):** external-bundle loading is **default-off behind `system.adapters.external`** — in-tree registrations always load; external bundles load only when the principal opts a stack in. Matches the dev-loop-dormant-by-default secure posture.

## Consequences

- **Cortex shrinks and stops release-gating surfaces.** A surface change is a bundle release; a cortex release no longer touches surfaces (D1). Platform npm deps leave `package.json` as each adapter extracts (D2, blocker #8).
- **One new public contract to maintain with discipline: the adapter SDK.** `ADAPTER_SDK_VERSION` + `src/adapter-sdk/` become a versioned surface; breaking it is a major bump + migration (D1, OQ5).
- **The core is rewired once (S3–S4), then extraction is mechanical.** The fixed 4-method `GatewayAdapterFactory` becomes a platform-keyed `AdapterFactoryRegistry`; `SurfacesSchema` composes registry-contributed binding schemas instead of 4 hardcoded `.strict()` keys. Because both construction paths already share one factory (S9), **the epic's blocker #4 is mostly retired** — S3 is "make the factory a registry," not "unify two sites." The real residual `cortex.ts` coupling is **blocker #6** (the worklog `DiscordAdapter.getClient()` reach-through at `:134,335,5889,5936`), which S2 must clear before the discord extraction (S12).
- **Discord extracts last, hard-gated on S1+S2.** Deleting `src/adapters/discord/` before the generic modules (`attachment-types`/`attachments`/`channel-context`, `dispatch-handler.ts:25,51,52`) relocate and the worklog decouples would break the core.
- **A new trust surface exists.** In-process bundle code runs with full authority (D4); the mitigations bound likelihood, not blast radius. Any future need for untrusted adapters forces the separate-process escalation.
- **Standing cross-reference:** this ADR is the answer to ADR-0017's deferred "extract the adapter too" alternative. Future reviews cite this ADR rather than re-opening 0017.
- **This ADR is the ground truth once accepted.** A downstream issue (S1–S13) that disagrees updates itself first (comment the delta), then implements — never silently diverges (epic working notes).

## Alternatives considered

- **Separate-process adapters over IPC (surfaces as sandboxed out-of-process plugins).** Each adapter runs in its own process, talking to the daemon over IPC/a local socket; a compromised adapter is confined to its process. **Rejected for v1** on cost and latency: it adds a process-supervision layer, an IPC serialization boundary on the hot inbound/outbound path, and per-adapter lifecycle management — disproportionate while every bundle is first-party and the accepted-risk mitigations (D4) hold. **Explicitly retained as the named escalation path** if a real trust boundary is ever required; the surface gateway (cortex#524) already runs adapters out-of-process and unsigned (`CONTEXT.md:181`), and ADR-0012 is the account-isolation precedent — so the door is architecturally open, not closed.
- **Keep adapters in-tree behind build flags / conditional compilation.** A build/env flag includes or excludes each adapter at bundle time. **Rejected:** it does not remove the source or the npm deps from the repo (blocker #8 unresolved — `discord.js` still pinned into every build's dependency graph), still requires a cortex release to change the flag set, and gives no independent per-surface versioning. It is monolith-with-a-switch, not pluggability.
- **Status quo — adapters stay compiled into core.** **Rejected:** it is the problem statement — monolith growth, whole-cortex releases for any surface change, every stack carrying every surface's deps, and it leaves ADR-0017's deferral permanently open.
- **cortex-version-range as the primary compat gate** (bundle declares `cortex: >=X <Y`). **Rejected as the gate** (kept as advisory metadata, D1): it couples surface compat to cortex's release cadence and goes stale on every cortex release that doesn't touch the adapter contract, and arc-install-time checks mislead after `arc upgrade cortex`. The SDK semver range tracks the thing that actually breaks compatibility.
- **Keep an in-tree real-adapter fallback after extraction.** **Rejected** (D2): a second source of truth, and it blocks the dependency extraction (blocker #8) for as long as it lives. A time-boxed transitional fallback is the conservative variant offered to the principal (design §7 OQ2), but the recommendation is delete-on-extraction with the mock as anchor.
