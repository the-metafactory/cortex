# Inactive bounded queries

`ConversationHost.readQueries(registry, bindings)` constructs the exported `QueryRunner` over the Cortex runtime's durable store and current authority mediator. The first call fixes the registry, authority bindings and optional clock; later calls with different arguments throw. Nothing registers a production reader or a model tool. The surface SDK is unchanged.

The trusted Cortex runtime calls `create(context, selectedSources, sink)` to mint a query UUID and persist its exact closed read envelope 1.0.0. It then calls `run(context, envelope, sink, invocation?, signal?)`. Each call requests one bounded page from each unfinished selected source. A model invocation must share the opaque handle returned by `invocation()` across every query and continuation it initiates. A UI Load more call gets a new invocation. The Cortex runtime must obtain selections from authenticated conversation state; editable input cannot supply authority, a budget handle or a connector.

The connector implements `TrustedConnector.query` and receives a real combined AbortSignal, a bounded limit and the exact protected provider cursor. It returns the closed `QueryPage` envelope. The binding's `query` field declares the object array pointer, provider ordering, stable-snapshot support and optional tighter page limits. Optional aggregate pointers declare scalar values or arrays of scalars outside the object array; other unmapped payload content is unavailable. The entire domain payload must match the exact capability output schema. Each array element needs one annotation with its JSON Pointer, canonical reference, destination, exact object schema, provider position and provider evidence/revision. Every object and display pointer is checked before any page is released.

Pages are delivered only through the render target under current authority. The runner returns status and opaque continuation metadata, so its later return cannot release an earlier page again after revocation. The Cortex runtime releases canonical objects ordered by provider position with a canonical-reference tie-break, mapped aggregates, source restriction obligations and an explicit untrusted marker. It withholds a whole page if any object is invalid or denied, so aggregates cannot reveal withheld content. The original object array is not released as a second route around deduplication. Live pagination remains best-effort and incomplete; stable-snapshot consistency requires both binding support and a matching connector attestation.

A result groups authorized sources in selection order and reports untouched sources as not-attempted/budget-exhausted. Denied sources contribute only a restricted flag, with no names or counts. Invalid pages and provider exceptions report safe structured errors. No-match requires exhaustion without a continuation, incomplete coverage or an unattempted source.

Cortex continuation UUIDs are single-use and expire ten minutes after query creation. Per-query durable documents with a bounded expiry index retain exact provider cursors, page positions, snapshot identities and bounded canonical identity digests. They bind the complete request, authenticated principal/session/context, account/credentials, connection/configuration, schemas, policy and restriction heads. The store caps active queries at 1000 and identity digests at 1000 per source; reaching capacity requires restart rather than dropping identity evidence. Every transaction removes expired query documents, and an unreferenced timer sweeps the next expiry while the runner is open. A closed Cortex runtime cannot resume an expired continuation; reopen revalidates every head. Current-only base checkpoints use the durable store's revision pruning instead of retaining historical cursor revisions. No separate database is introduced.

`cancel(queryId)` immediately aborts active connector signals and durably invalidates continuation state. Already released pages remain the caller's visible content with the returned cancelled status. Late responses cannot enter a render target or populate a query cache. Cancellation cannot prove that a provider stopped processing its request. Deadlines bound policy admission as well as provider waiting.

Execute the synthetic local evidence with `bun scripts/probe-desk-query.ts`. It creates a temporary HOME and durable store, loads and continues pages, changes an actual schema pin, then cancels an abort-ignoring connector and verifies that its late result is suppressed. It uses no provider account or external effect.

`ConversationHost.readObservations(registry, bindings, clock?)` registers the inactive observation store. Its per-connection `cortex.read-observations` documents use current-only durable checkpoints; there is no production boot consumer. A poll binding can declare strict `observation` policy with supported `poll`/`subscription` modes, an exact object-array pointer, resume support, an optional trusted revision-ordering identifier, owner watermark support, freshness and tighter retention limits. The registry, lifecycle and published SDK versions are unchanged. <!-- glossary-ignore: owner -->

The Cortex runtime's trusted connector supplies bounded observation batches through `TrustedConnector.observation.fetch`. In subscription mode this consumes the next provider-delivered batch from the connector's subscription, rather than listing owner objects. A quiet connector can return an empty `coverage: "none"` batch; this does not verify cached objects. Poll, reconcile and explicitly configured resync calls are bounded current reads. Each call has a 20-event, 1 MiB and 10-second ceiling and a real abort signal. The whole pinned output, canonical mapping, exact schema references, destinations and optional tighter object restrictions are validated before protected persistence. The connector cannot obtain credentials from editable input. Owner deletion is a separate explicit evidence variant; absence has no deletion meaning. <!-- glossary-ignore: owner -->

The store keeps one connection-qualified current row, metadata-only dedup/conflict evidence and protected resume state. Stable evidence collisions quarantine both digests. Digest-only deliveries coalesce only identical current content; returning content requires reconciliation. Only a registered comparator with the exact binding identifier orders revisions. Polling never makes an older known revision current. Linked objects survive capacity eviction, and linked deleted markers contain no object value. Dropping evidence or a marker invalidates every affected connection checkpoint and fences subscription replay until bounded resync. Expired content is removed on access or maintenance, and unchanged owner verification can refill it without a new domain event. Stricter connection retention is persisted and cannot be relaxed by reading through another binding. <!-- glossary-ignore: owner -->

`ObservationStore.read` performs current admission and reads the protected document inside the authority release barrier. It checks exact account/configuration/schema identity, current destination and object restrictions, final policy heads and expiry before entering the registered render target. Its authorized object views distinguish owner observation time, Cortex runtime receipt time, successful verification, attempted checks and freshness. Denials release no names, values or counts. `link` is a trusted Cortex runtime seam for conversation/receipt references; removing the last link removes a deleted marker and invalidates resume coverage. It does not edit conversation history or operation receipts. <!-- glossary-ignore: owner -->

`ObservationScheduler` has no schedules until `configure` is called per connection. Enabled schedules default to 60 seconds, enforce a one-second minimum, coalesce in-flight work and honor provider `ObservationRetryAfter`. A dropped subscription gets three reconnect attempts after 1, 5 and 30 seconds, then becomes unavailable. A matching checkpoint is reauthorized on every attempt and after reopen. Gaps remain stale; only `boundedResync: true` allows automatic bounded repair. Objects missing from that bounded check remain stale and are never deleted. Closing/disabling aborts pending work and suppresses late batches. Schedules themselves are not automatically restored or activated on Cortex runtime reopen.

Execute `bun scripts/probe-desk-observations.ts` for synthetic duplicate, failed-poll freshness, durable reopen/resume and linked deletion-marker evidence under a temporary HOME and store. Exported-seam tests in `observations.test.ts` use the Cortex runtime's real durable store and a controlled clock, including 1000 objects, 10000 evidence entries and read/reopen bounds. No provider account or external effect is used.
